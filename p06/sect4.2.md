Summary by Grace N.

# Question 1
My experience with legacy code in school is similar to what was mentioned in the paper. I feel like I haven't really worked with it much in coursework and would definitely say I don't spend long periods of time working on projects at school (10 weeks being the max). I haven't taken OS, so I don't know about that. Outside of school though, I had an internship where I worked with and learned about their legacy code, so I definitely knew that these larger codebases exist and that schoolwork isn't the same as real-world code in most cases. I think my experience is a mix because while school hasn't given me much exposure to legacy code, my internship has helped me understand what it's like to work with existing projects.

# Question 2
One of the biggest surprises for developers was how much time they spent working with legacy code compared to writing new code. In school, most assignments involve starting from scratch, but in industry, developers often inherit code that other people wrote and have to figure out how it works before making changes. Some developers mentioned that even code they had just written could become legacy code pretty quickly because they would have to go back and modify it. Another challenge was dealing with large codebases that weren't always easy to understand. A lot of developers weren't prepared for this because they hadn't experienced it much in school.

# Question 3
I think schools could better prepare students by including more assignments where they have to work with existing code instead of always starting from scratch. For example, students could be given a larger codebase and asked to fix bugs, add features, or improve parts of it. This is something I did a lot in my internship was just working with the codebase and modifying it on my own branch so that it wouldn't interfere, and I think it was a really good way to get exposed to working with legacy code.

I also think it would be helpful to have projects that last longer or build on previous assignments so students get experience maintaining their own code over time. I am a senior in CE starting my capstone, and I think it will be good that we actually get to commit a full year to working on something rather than being limited to one quarter. It would be cool to have other classes at UCSB that are more than one quarter long and walk you through building a project and adding more to it throughout multiple quarters.
